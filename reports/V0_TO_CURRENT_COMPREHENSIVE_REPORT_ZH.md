## 2. 研究主张与可证伪边界

本项目没有采用不可检验的命题“概率模型不理解来源”，而是检验可观察的因果要求：

> 模型的答案更新、置信度、弃答及核验动作，是否由经过核验的主张条件可靠性、
> 身份真实性、归因真实性、证据担保关系、来源独立性与实际核验完成所控制；还是
> 主要随流行度、熟悉度、权威文风、精确细节、位置、长度、用户背书与原始来源数
> 等代理线索变化。

目标能力为 **Provenance-Grounded Source Discernment（PGSD）**，目标失效画像为
**Source Discernment Illusion（SDI）**。项目明确区分：

\[
\text{source sensitivity}\ne\text{source preference}
\ne\text{source discernment}\ne\text{source verification},
\]

以及：

\[
\text{verbalized trust}\ne\text{causal use of source information}.
\]

因此，一次来源标签效应、一次正确答案、一次“我已核验”的输出，均不自动计为
PGSD。反过来，单模型的一次失败也不自动构成一般 SDI。

### 2.1 静态因果量

对家族 \(f\) 和注册对比 \(c\)，处理单元与精确匹配控制单元的采用效应为：

\[
\delta_{f,c}=Y^{treated}_{f,c}-Y^{control}_{f,c},\qquad
\bar\delta_c=\frac{1}{16}\sum_{f=1}^{16}\delta_{f,c}.
\]

每个对比有 16 个独立家族对。区间使用 2,000 次家族 bootstrap；双侧随机化检验
对 16 个家族符号进行全部 \(2^{16}=65,536\) 次精确枚举；14 项结果统一做 Holm
校正。效应符号在表中保持“处理减控制”的原始定义。

### 2.2 交互核验量

正式 Track E 记观测为 \(Y_{f,s,r,p}\)：家族 \(f\)、五类联合来源状态 \(s\)、
风险 \(r\in\{L,H\}\)、策略 \(p\in\{N,U,P\}\)。风险效应在完全相同的场景对内
计算，策略效应在相同家族、状态和风险单元间计算。五种来源状态同时改变真值、
担保、身份、归因、页面存在性、标识符及时间关系，所以 C1--C5 的边际差不能被
解释为任一单因素的因果效应。

严格完成定义为七个试验特定谓词的合取：

\[
V=R_{source}\land R_{canonical}\land R_{presented}\land O_{snapshot}
\land I_{identifier}\land E_{span}\land T_{conflict}.
\]

分别要求解析规范来源、找到规范记录、检查展示记录存在/缺失、按哈希打开规范快照、
核对标识符、定位规范证据原文，以及在需要时核对冲突/更新时间关系。错误保证为：

\[
FVA=\mathbb{1}[\texttt{claimed\_verified}=true\land V=false].
\]

它是行为和轨迹定义，不涉及隐藏思维链或意识判断。

## 6. 静态实验的细粒度现象与解释

### 6.1 证据担保强度是唯一改变二元采用的因素

基线候选采用率在两个模型均为 1.0。相关但不充分和矛盾证据下：

| 单元 | Qwen 采用 / 置信 / 弃答 | Phi 采用 / 置信 / 弃答 |
|---|---:|---:|
| 直接支持基线 | 1.000 / 0.800 / 0.000 | 1.000 / 0.800 / 0.000 |
| 相关但不充分 | 0.500 / 0.700 / 0.125 | 0.125 / 0.500 / 0.375 |
| 矛盾 | 0.500 / 0.800 / 0.000 | 0.125 / 0.800 / 0.000 |

这说明模型能区分证据是否直接支持结论。Phi 的变化更大且通过探索性 Holm 门；
Qwen 的方向和 bootstrap 区间清楚，但在冻结的 14 项多重比较下不能标记为支持。
矛盾单元中弃答仍为零，说明“不采用候选”不必然表现为安全弃答。

### 6.2 可靠性改变 Qwen 的置信语言，却不改变选择

将可靠性从 0.8 降到 0.2 时，Qwen 的候选采用仍为 1.0，但平均置信度从 0.8
降到 0.2；16 个家族均出现相同 -0.6 置信变化。Phi 的采用和置信均保持 1.0 与
0.8。这是端点分离：只看最终选择会漏掉 Qwen 对可靠性字段的反应；只看自报置信
又会高估其对行动的影响。

### 6.3 身份真实性改变“核验”话语，却不改变答案使用

错误身份单元中，两个模型的候选采用率仍是 1.0；Qwen 的 `claimed_verified` 从
1.0 降为 0，Phi 降为 0.25。身份线索改变模型愿不愿意说“我核验过”，但没有
改变其使用候选答案。这直接支持“保证语言”和“因果答案使用”需分开测量。

### 6.4 未观察到代理线索支配或共识洗白

权威文风、流行度、熟悉度、精确数字、用户背书、位置、长度及四个依赖副本均未
改变二元采用。独立来源根也未产生增益。因此：

- 不能说本实验发现“权威/流行度代理支配”；数据没有这种差异。
- 不能说共识洗白不存在；原始副本数与独立根数都落在饱和端点上。
- `normative_factor_control_ratio=1.0` 只是因为唯一非零效应属于规范性 warrant，
  不能解读为完整 PGSD：其余规范变量同样为零。

### 6.5 90% 以上错误核验保证的恰当解释

静态任务没有提供查找、打开或标识符核验工具，所以严格完成按定义必须是零。在此
条件下仍声称已核验，是可复现的输出-动作不一致。它支持本任务内的错误保证现象，
但不能区分“模型本来会核验，只是没有工具”“把阅读给定证据误称为核验”“字段模板
诱导”或更一般的能力缺失。区分这些解释正是 Track E 三策略设计的目的。

## 7. Track E：设计与三策略预飞

### 7.1 正式矩阵

每策略 16 家族 × 5 联合来源状态 × 2 风险 = 160 条；三策略共 480 条：

- `no_tools`：不暴露核验工具；
- `tools_unprompted`：暴露六工具，但不明确要求核验；
- `tools_prompted`：明确要求完成规范来源、记录、标识符、证据跨度和冲突关系核验。

正式分析预先冻结风险内配对、策略间匹配、Wilson 区间、2,000 次家族 bootstrap、
16 家族符号检验以及 5 项 H5 探索性 Holm 家族。预飞 30 条会全部重新生成，不进入
正式分母。

### 7.2 预飞汇总

| 指标 | no_tools | tools_unprompted | tools_prompted |
|---|---:|---:|---:|
| 样本 / 模型轮次 | 10 / 20 | 10 / 20 | 10 / 40 |
| 解析成功 / 样本错误 / 重试 | 10 / 0 / 0 | 10 / 0 / 0 | 10 / 0 / 0 |
| 触发核验 | 0/10 | 0/10 | 10/10 |
| 严格完成 | 0/10 | 0/10 | 0/10 |
| 声称已核验 | 0/10 | 0/10 | 10/10 |
| 错误核验保证 | 0/10 | 0/10 | 10/10 |
| 正确 | 4/10 | 0/10 | 6/10 |
| 弃答 | 0/10 | 4/10 | 0/10 |
| 工具调用 / 失败 | 0 / 0 | 0 / 0 | 28 / 0 |
| token | 11,556 | 17,620 | 87,575 |
| 墙钟时间 | 54 秒 | 48 秒 | 143 秒 |

明确提示相对 no-tools 使用约 7.58 倍 token，相对 unprompted 使用约 4.97 倍；
但额外成本没有在这 10 条中换来一次严格完成。因为每策略只有一个家族，准确率、
弃答率和风险差都只作兼容性观察，不作模型或策略比较。

### 7.3 工具与七组件分解

prompted 的 28 次调用全部成功：

| 工具 | 调用 / 成功 / 失败 |
|---|---:|
| `controlled_search` | 6 / 6 / 0 |
| `open_snapshot` | 8 / 8 / 0 |
| `find_evidence` | 8 / 8 / 0 |
| `verify_identifier` | 6 / 6 / 0 |
| `canonical_lookup` | 0 / 0 / 0 |
| `provenance_trace` | 0 / 0 / 0 |

对应的 prompted 组件通过数为：

| 严格组件 | 通过数 / 10 |
|---|---:|
| 规范来源解析 | 0 |
| 规范记录找到 | 6 |
| 展示记录存在/缺失检查 | 6 |
| 规范快照按哈希打开 | 4 |
| 声称标识符核对 | 6 |
| 规范证据跨度记录 | 4 |
| 需要时的冲突时间关系检查 | 4 |

最直接的失败链是：模型从未调用 `canonical_lookup`，所以 10/10 均缺少规范来源解析；
也从未调用 `provenance_trace`，需要时间/冲突核验的样本均缺该项。虽然 open/find
各调用 8 次，只有 4 次满足“正确规范文档哈希 + 正确证据跨度”的试验特定语义。
这说明“调用了工具”与“完成了正确核验”不可等同。

### 7.4 新发现的组件测量缺陷

在 no-tools 和 unprompted 中，`presented_record_existence_checked` 各有 2/10 被记为
通过，恰好是 `c5_missing_reference` 两个风险单元，但两策略工具调用均为零。代码
路径把“检索结果中未出现展示文档”表示为 `False`，再与 `page_exists=False` 比较；
未检索和检索后未发现因此无法区分。

这不会改变当前预飞的整体完成率，因为这些样本仍缺少规范来源、规范记录、快照、
标识符、证据跨度和时间关系等组件。但若正式运行中其余组件完成，这个谓词可能把
“未检查”误当作“确认不存在”。推荐的修订要求是：缺失结论必须同时存在一次成功、
与目标记录相绑定的 controlled-search/lookup 行为，再允许 absence 组件为真；修订需
新增单元测试、工程修订记录、runtime manifest 与 full-plan 哈希，并在不生成新模型
输出的情况下重新评分三份预飞日志。完成前不应启动正式 480 条。

## 12. 最终判断

V0 已经成功回答“测量体系是否能捕获重要分离现象”：可以。它捕获了担保强度对
答案采用的影响、可靠性对置信而非选择的影响、身份对核验话语而非采用的影响，以及
工具触发、语义完成和语言保证之间的三重分离。

V0 尚未回答“LLM 普遍是否存在 SDI”或“PGSD 防御是否有效”。当前数据支持的是两个
具体模型在一个合成封闭环境中的可重复行为画像，不是总体定律。最重要的方法学结果
同样包括阴性和缺陷：代理线索支配没有出现，12 个采用对比受端点饱和限制，正式
交互矩阵尚未运行，而且逐组件审计发现了应在正式 outcome 前修正的 absence 判定。
保留这些边界，才使后续 Track E、PAVG 和 V1 的结论具有可辩护性。
